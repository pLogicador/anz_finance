## What this is

ANZ Finance is being rebuilt from a Streamlit monolith into "ANZ Finance 2.0": a React/Vite/TypeScript frontend (Vercel) + a FastAPI backend (Railway), replacing Streamlit entirely. It parses OFX bank statements, classifies transactions via an LLM, and presents an interactive financial dashboard. It is one service inside the larger "Syncron" ecosystem — it has **no login/signup of its own**; the only way in is a token issued by the Syncron Hub after the central `subscription_access_api` service confirms the user's plan is active.

## Hard guardrails (apply to every phase, not just where restated)

1. **No database, Redis, persistent filesystem, or equivalent storage for user data, in any phase.** If a feature seems to need persistence (snapshots, import, AI key storage, validation-result caching), the default is an in-memory/TTL-based session alternative — only if that's genuinely impossible should persistent storage even be discussed, and even then it needs explicit sign-off before implementing.
2. **ANZ Finance never replaces, replicates, or assumes authority over Syncron's identity/subscription state.** `subscription_access_api` is the only source of truth for who the user is and whether their plan is active. ANZ's own JWT (see below) is only a short-lived technical session issued *after* a successful Syncron validation — never a second identity source, never independently renewable without going back through Syncron.

## Architecture (target — being built now)

```
anz_finance/
  backend/            # FastAPI (Railway) — access control, session, data pipeline, AI, routes
  frontend/           # Vite + React + TS (Vercel) — dashboard UI, design system
  legacy_streamlit/    # Archived original Streamlit app — reference only, see its own README
```

- **Access control (non-negotiable part of the spec)**: frontend reads `?token=` from the Syncron Hub redirect URL client-side, POSTs it once to the backend's bridge endpoint. Backend validates against `subscription_access_api`'s `POST /validate-agendador-token` (never modify that repo — it's called read-only over HTTP) — a 200 response already proves the plan is active (that service enforces `plan_end < now` server-side, regardless of free/paid). Backend then mints its **own** short-lived JWT (independent `SECRET_KEY`, no cookie, no DB — pattern replicated from the sibling project AgenteOS's `backend/app/core/security.py`/`api/v1/auth.py`, adapted to have zero persistence since ANZ has no DB). Frontend holds that JWT in `localStorage` (never the raw Syncron token) and sends it as `Authorization: Bearer`. Full 6-state design (validating / authorized / plan expired / token invalid-or-missing / work-session expired / Syncron service unavailable) is in the plan file above.
- **No persistent database anywhere.** Uploaded OFX data, classification results, filters — all live in an in-memory, TTL-expiring workspace store keyed by session, gone when the session ends.
- Business rules that must be preserved verbatim from the legacy app (see `legacy_streamlit/CLAUDE.md` for the original documentation): the 11 fixed category labels from the Groq classifier prompt, the `filter_transactions` "empty categories list = no filter" semantic (and its distinct month-independent "trend" variant), the type filter (`Receitas` = `Valor >= 0`, `Despesas` = `Valor < 0`), the `month_over_month_delta` `invert` favorability pattern.

**Bug real descoberto e corrigido, causa raiz no backend, não só no frontend.** Antes desta fase, `app/workspace/deps.py`'s `get_workspace_payload` colapsava dois casos bem diferentes no mesmo `error_code` (`work_session_expired`, HTTP 410): (1) uma sessão que **já tinha** dados e cuja TTL expirou, e (2) uma sessão **recém-criada que nunca enviou nada**.
